# ADR：记忆可移植层（导出/导入 + 图查询 DSL）

> 状态：已实现（2026-10-28）｜实现：memomind/transfer.py + tests/test_transfer.py（9 项）
> 全量测试 79 项全绿（70 既有 + 9 新增）

## 1. 我为什么做可移植层

面试官问"记忆被锁死在你的 SQLite 里怎么办/换数据库/换部署怎么办"——没有导出能力的记忆系统是数据孤岛。可移植层的标准：**导出是全字段的**（时间有效性/状态/溯源/置信度全带），导入端可以完整重建时间线，而不是只搬"活跃事实"。

## 2. 设计决策

### 2.1 导出：JSONL 全字段 + 状态过滤
- 默认仅 active（日常备份），`include_inactive=True` 连 superseded/archived 一起导（完整审计快照）。JSONL 逐行——比单 JSON 大文件更适合流式与增量。

### 2.2 导入：幂等去重的两层判定
- **同 id 跳过**（精确重复，重复导入同一份 dump 零副作用——幂等性测试覆盖）；
- **同 active 三元组跳过**（换 id 的重放也进不来——测试里专门用"改 id 但同三元组"验证：新 id 被跳过，证明三元组去重生效而非 id 去重）；
- 坏行（JSON 解析失败/缺字段）计入 invalid_lines 继续处理——坏一行不拖垮整批；
- 保守策略只做 "skip"：merge/upsert 语义留给上层显式决策，导入层不猜。

### 2.3 直写 SQL 而不走 store.add()
- **决策**：导入直接用 store 连接 INSERT（同包内部），完整保留原 id/created_at/valid_from/source_session。
- **理由**：store.add() 会重新生成 id 和时间戳——那不是"导入"是"重放"，时间线全变。FTS 触发器在 INSERT 时自动同步，无需手工维护。
- **代价**：依赖 store 的表结构内部细节——同包内可接受，跨包应走导出格式而非直连。

## 3. 图查询 DSL：语义是"每个 `->` 一跳"

- 语法：`实体 -[谓词]-> 实体 -> *`，`*` 通配节点，谓词可省略；1~3 跳。
- **实现里我踩的语义坑（测试当场抓住）**：第一版按"节点段"建模——"A -p-> B"被拆成两段，导致终点 B 还要再有一跳出边才命中（幽灵跳）。正确语义是**N 个 `->` = N 跳**，每跳 (起点,谓词,终点)，链式约束"第 i 跳终点 = 第 i+1 跳起点"。
- 谓词匹配用**前缀规则**：实体域谓词在图中形如 `application_status:流程结束`，查 `application_status` 应命中——前缀匹配把"谓词:状态"复合结构对查询方隐藏。
- 全图通配（起点 `*`）给 500 节点上限——防大图全遍历；实体锚定查询无此限制。

## 4. 边界

- ~~导入不做 merge/upsert~~ **已实现（2026-10-28）**：`dedupe="update"` 策略——同 id 整行覆盖（显式 DELETE+INSERT 保证 FTS 触发器同步）；**同 active 三元组不同 id 仍跳过**（身份由三元组定，合并策略属上层），有专门回归测试。
- 导出格式版本未内嵌（当前 1.0 字段集）——未来字段变更时应加 format_version 首行。
- 图 DSL 不做正则/属性过滤（如 confidence>0.8）——保持 1.0 极简，复杂过滤走 Python API。
