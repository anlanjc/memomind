# memomind 设计决策记录（ADR）

> 本项目回答"长期记忆怎么设计/何时删怎么删"——每条决策对应 ops/store/retrieve/decay 的具体机制。

## ADR-1 为什么记忆用三元组+置信度，不用向量存对话原文

- **背景**：记忆的难点不是"找回来"（那是检索问题）而是"管状态"（更新/冲突/遗忘是生命周期问题）。
- **决策**：每条记忆 = (subject, predicate, object) + valid_from/valid_to + confidence + status 三态（schema.py:51-72）。
- **备选与放弃**：①对话原文+向量——相似度解决不了"字节流程结束了"要替代"已投字节"的状态更新；②纯 KV 对——表达不了"历史保留"（投递记录 vs 当前状态是两类信息）。
- **后果**：抽取有损耗、无语义召回——FTS5+意图映射+图邻域是显式补偿；接 embedding 是增强不是重构。

## ADR-2 为什么操作决策做成"规则矩阵打底 + LLM 可选替换"

- **背景**：新事实进来要和现有记忆做 ADD/UPDATE/DELETE/NOOP 判断——这是记忆系统最核心的决策点。
- **决策**：RuleOpsDecider 的 7 分支决策矩阵（ops.py:163-220）：A0 低置信不收 → B 撤销型事实失效旧记录并留档 → C 强化（同向事实置信度叠加）→ D 完全重复 NOOP → E2/E3 矛盾 supersede（新生效、旧封 valid_to 留痕）→ E1 全新 ADD。
- **备选与放弃**：①全用 LLM 决策——不可复现、评测没法做确定性断言；②纯规则永不换——语义冲突（"不想去了"vs"流程结束"）规则覆盖不了，所以留 LLMOpsDecider 接口且异常时回退规则版（ops.py:363-365 决策层永不失败）。
- **后果**：20 场景评测全确定性可复现；代价是规则表维护成本——意图/谓词词典就是系统的"词表债"，已列入接手清单。

## ADR-3 为什么冲突消解按"谓词分域"而不是全局相似度

- **背景**：矛盾不能一刀切。"已投字节"和"字节流程结束了"矛盾吗？——状态上矛盾，历史上不矛盾（投递记录应该留）。
- **决策**：谓词三档冲突域（ops.py:76-96）：functional（姓名/目标岗位——新值替代旧值）、entity（实体状态——状态 supersede 但历史谓词保留）、per_object（投递记录——多条并存）。冲突键 = 谓词域 + 实体（ops.py:99-109）。
- **备选与放弃**：①全局唯一键（实体+谓词）——投递历史会被状态更新覆盖丢掉；②交给 LLM 每次判断——不可测。
- **后果**：字节真题"历史何时删怎么删"的完整答案：**状态被替代、历史留痕（superseded + valid_to 封口）、物理删除归 compaction 延后批处理**——三层删除语义。

## ADR-4 为什么遗忘用"半衰期 30 天 + 访问刷新"而不是定期清理

- **背景**：三个月前的"今天面XX"不该再影响回答，但常被想起的核心偏好不能丢。
- **决策**：有效置信度 = confidence × 0.5^(idle_days/30)（decay.py:31-33），低于阈值归档；**命中检索即刷新 last_accessed**（"被想起就重置遗忘时钟"）；过期归档（valid_to）与 compaction（superseded 物理清理）分层（decay.py:70-111）。
- **备选与放弃**：①定时全删——删错不可逆；②LRU 式容量上限——记满即丢最老，对"长期偏好"不友好。
- **后果**：参数（30 天半衰期、0.15 阈值）是经验值——标定实验在 TAKEOVER 必做实验 1，这是诚实的待校准项。

## ADR-5 为什么无 embedding 还能检索准

- **背景**：无 embedding 配额是硬约束。
- **决策**：三路补偿：FTS5 词面（trigram 探测，store.py:86-96）+ **意图映射表**（"我叫什么名字？"→name 谓词，补零词面交集，retrieve.py:34-43）+ 图邻域扩展（命中实体的一跳关系）；分数 = 词面×2.0 + 意图×4.0 + 图×3.0 再乘时间衰减。
- **备选与放弃**：①裸 FTS5——"我叫什么"查不到名字（零词面重叠），意图映射就是为这个补的；②硬等 embedding——系统先跑起来，embedding 到位后按同接口替换。
- **后果**：8 类谓词映射表是显式维护面——换域要补表（TAKEOVER 实验 4 的敏感性分析对象）。

## ADR-6 为什么 LLM 决策器把撤销/重复/低置信委托给规则矩阵（44 试样真模型对比，2026-10-29 MM-3）

- **背景**：LLMOpsDecider 最初把整批候选事实原样交给 LLM 裁决。真模型对比
  （180 个决策点分层抽 44 试样 + 9 个合成语义探针，规则矩阵输出为基准）测得
  raw 一致率仅 **31/44=70.5%**，且分歧高度系统化：31/44 → 41/44（撤销与
  UPDATE 无目标委托）→ 43/44（重复提及预路由）→ **44/44=100%**（低置信预路由），
  每类分歧独立归因（报告 evals/real_ops_decider_report.md）。
- **决策**：LLM 只裁决正极性新事实的语义核心（E1 新增 / D1 矛盾替代 /
  D2 多值并存）；三类**结构性分支委托规则矩阵**（ops.py LLMOpsDecider.decide
  预路由）——①撤销事实（C1 是 DELETE×N+ADD 留档复合动作，"每条事实一个动作"
  的输出 schema 表达不了，真模型 6/6 分歧）；②同三元组重复提及（B1/B2 由
  置信度算术决定，真模型运行间摇摆于 UPDATE/NOOP）；③低置信（A0 丢弃线是
  可配置策略 min_confidence，LLM 不知道配置、把 0.2 置信判 ADD）。
  每次决策的 delegated_*/fallback_error 留痕在 last_call_stats 可观测。
- **依据**：分歧根因是**输出 schema 表达力、策略配置可见性、置信度算术**，
  都不是 LLM 判断力——它在语义核心上 132 次调用零异常零回退（纯新增 21 试样、
  矛盾替代、混合批全对）。
- **备选与放弃**：①改 LLM 输出 schema 让它表达复合动作（actions 数组）——
  解析面变宽更脆，且矩阵本就完美拥有该语义；②把 min_confidence 塞进
  prompt 让 LLM 执行——阈值执行靠 LLM 服从性不可靠；③全委托回规则版
  （等于删掉 LLM 决策器）——语义核心（"改投算矛盾还是新增"）是 LLM 的
  价值所在，保留。
- **后果**：LLM 不再参与撤销裁决与重复强化（正确性优先于覆盖）；同批内
  "先投后撤"的终态靠"撤销动作置于批内最后"与矩阵对齐，"先撤后投"等极端
  顺序以规则矩阵为准（抽取层 normalize_facts 已按三元组批内去重，精确
  重复到不了决策层）；评测装置教训同步入档——单变量对比必须 deepcopy
  隔离快照（决策器的 strengthen 会原位改写记录对象）。
